# 0001: Dev stack and CI gate

Status: accepted
Date: 2026-10-25

## Context

Integration tests run against the real broker and database (README, Contributing). The MVP plan (Task 1) needs a local stack with EMQX, Postgres and Toxiproxy, pinned tags, and a CI gate that matches the GroupDrive Jenkins setup.

## Decision

**Images** (`deploy/dev/compose.yaml`, checked on Docker Hub and ghcr.io on 2026-10-25):

| Service | Image | Notes |
|---|---|---|
| EMQX | `emqx/emqx:6.3.2` | Newest stable, released 2026-10-22. The Docker Official `emqx` image stopped at 5.8.x after the BSL change |
| Postgres | `postgres:16.15` | Newest 16.x patch |
| Toxiproxy | `ghcr.io/shopify/toxiproxy:2.13.0` | Newest release; the ghcr tag has no `v` prefix |
| JWKS | `nginx:1.30.6-alpine` | Serves the dev JWKS on 8090 until the hub does (added in spike S1) |
| HAProxy | `haproxy:3.4.7-alpine` | TLS front for WSS on host port 18443 (8443 is taken on the dev host), like the cluster's HAProxy ingress (added in spike S1) |

**CI images** (`ci/kubePod.yaml`): `rust:1.99.1-bookworm` and `docker:29.9.2-dind`. Tools are pinned in the `Jenkinsfile`: cargo-nextest 0.9.149, cargo-deny 0.20.2.

**EMQX config** (`deploy/dev/emqx/emqx.conf`, mounted read-only over `etc/emqx.conf`):

- One JWT authenticator in JWKS mode, pointed at `http://jwks:8090/v1/jwks` (the nginx service; the hub replaces it in MVP Task 7). `on_missing_jwt = deny`, `disconnect_after_expire = true`, and `verify_claims { sub = "${username}", clientid = "${clientid}" }`.
- `durable_sessions { enable = true }` (spike S1, ADR-0002).
- `authorization { no_match = deny, sources = [] }`, so the token's `acl` claim is the only source of permissions. EMQX 6.3.2 ships a file source by default; emptying `sources` removes it.
- `mqtt.max_packet_size = 96KB`.
- The hub's REST API key comes from `api_key.bootstrap_file`, generated by `deploy/dev/init.sh` into the gitignored `deploy/dev/.secrets/`.

Checked against the running stack: the REST API reports the JWT authenticator and empty sources; `emqx ctl conf show mqtt` shows `max_packet_size = "96KB"`; a client with no password and a client with a password that is not a JWT both get CONNACK 134.

**nextest profiles** filter on test names (`test(/(^|::)it_/)`), not binary names as m0-m1 Task 1 says. nextest 0.9.149 rejects a `binary()` filter that matches no binary, which would break the gate until the first `tests/it_*.rs` lands. Integration tests are already named `it_*` throughout the plans, so the name filter selects the same set.

## Consequences

- **EMQX fails open when it has no authenticator** (verified on a default 6.3.2: `GET /authentication` returns `[]`, and a client with no username or password gets CONNACK 0 and can publish). The deploy manifests must carry the authenticator in read-only `emqx.conf`, as dev does, never only in runtime config that the dashboard can delete.
- `deploy/dev/init.sh` must run before `docker compose up`; compose fails on the missing `.secrets/` files otherwise. It is safe to rerun: it keeps existing secrets (the dev JWT key, dev CA, Postgres password, API key) and rewrites `dev.env`.
