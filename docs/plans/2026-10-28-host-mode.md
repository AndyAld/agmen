# Host mode implementation plan

**Goal:** Implement the approved `.superpowers/brief.md` without changing repository history or starting real services.

**Architecture:** agmend owns an optional host supervisor configured beside its socket. The local API exposes host status and restart. Desktop reuses its project selection, service startup, and Settings paths. The macOS bundle includes the hub helper.

**Tech stack:** Rust, Tokio, the existing local JSON API, GPUI, POSIX shell.

1. Write and run failing daemon tests for private host configuration, init, supervised child lifecycle, restart limits, injected tailscale checks, and local API status. Implement configuration, CLI, supervisor and API together. Use temporary directories and fake executables only.
2. Write and run failing desktop tests for direct last or recent project launch and host startup gating. Extend the existing project and connection paths, expose host status and restart in Settings, and preserve a 30 second startup bound.
3. Extend bundle build, signing and inspection scripts to include agmen-hub. Document host init and env-file handling without reading secret values.
4. Review each execution path against the brief and fix findings. Run formatting, workspace clippy, full nextest, doc tests, and shell checks exactly as specified. Record evidence, limitations, and the setup command in `target/host-mode/report.md`.

Every code change follows a failing regression test. Leave all changes uncommitted. Scratch progress is outside the repository.
